#+TITLE: Changelog
#+AUTHOR: Paul H. McClelland

All notable changes to ~tabularium~ are documented in this file.

* v0.6.0 (2026-08-31)

** Added

- A database file may hold several tables.  A schema names its relation with =:table=, connections are keyed by file and refcounted, and =PRAGMA foreign_keys= is set at connect.  The registry lists one row per database rather than one per table, with its own display name
- =:fk= declares a foreign key, emitted as =REFERENCES= at =CREATE TABLE=.  Deletion follows the declared referential action — =restrict= refuses and names the table holding the children, =cascade= says how many will go and snapshots them so undo restores the lot
- The =t= prefix moves between tables: =t t= switches, =t n= and =t p= step, =t l= lists them with their links, =t `= reorders, =t '= follows the key at point into the next table, =t ?= checks referential integrity, and =t == reports tables with no schema and schemata with no table
- =l= opens the child rows of the row at point, filtered to it; =L= returns to the row you left.  The rule is marked =← PARENT= in the rules list and removable like any other; =C-c l= clears it outright
- Formulas reach across tables: =(parent COLUMN)= and =(children TABLE)= are rewritten into the lookups the =:fk= already describes, and =(lookup-in TABLE KEY VALUE RESULT)= names a table explicitly — XLOOKUP with the sheet given, where =lookup= searches only its own
- A schema may name a view.  Views and tables marked =:read-only= refuse every writing command with a message rather than a SQLite error; =v R= toggles the property and the mode line reads =Tabularium[RO]=
- One import command on =i i=, asking where the data is going and then what is arriving.  =i N= and =i A= answer the first question in the key; =i a= appends to the open table
- A data import offers five ways to settle the schema — Auto-generate, Locate, Wizard, Shorthand, Manual — and a schema import offers to fill the tables it declared.  Two halves of one feature, asked from whichever end you arrived at
- Shorthand covers what the wizard covers, one line per table: =pk=, =req=, =long=, =hist=, =lab==, =w==, =d==, =c==, and a pipe-separated choice list.  Pre-filled from what was read, so the common case is reading it and pressing RET
- Manual opens the schema in a draft buffer beside the table, org-capture style: =C-c C-c= saves, =C-c C-k= or =C-c q= abandons, and nothing reaches the file until it parses
- =e T= exports several tables at once, one file per table; =e t= exports one without switching to it
- =t $= names a table, =. $= a database, =t k= sets the column a database links on, and =t S= shows the SQL a formula compiles to

** Changed

- The package uses SQL's vocabulary throughout: a table has *rows* and *columns*, identified by a *primary key* and referring to others by a *foreign key*.  =:fields= is now =:columns=, =:primary= is =:pk=, and =:foreign-key= is =:fk=; a schema written before 0.6.0 still loads and migrates itself the first time it is saved
- A schema has an internal key and a name.  The key is unique across the package, because that is what the schema list is keyed by; the name is unique within one database, which is the scope anyone thinks in
- Importing into the open database *adds* to its schema file rather than regenerating it, so computed columns, links, and hand-written labels survive
- Prompts that offer actions are capitalized single words; prompts that offer values stay lowercase.  Plurals read "1 table" rather than "1 table(s)", and tables are *deleted*, not dropped
- One quoting convention: `like this' is written everywhere and rendered everywhere.  Messages and =y-or-n-p= already passed through ~substitute-command-keys~; minibuffer readers do not, so they go through ~tabularium--prompt~ and come out with the same curly quotes instead of a literal backtick
- ~tabularium-compute-describe~ is ~tabularium-describe-sql~, named for the answer: the question is whether a column will be SQL-backed, which decides whether it sorts and filters
- Duplicates suffix =_2= upward throughout — tables, columns, databases, and schema names.  The package used four conventions, so =foo_copy_copy= was a real outcome

** Fixed

- Every cross-table computed column rendered as =<<ERROR>>= while compiling to correct SQL.  The guard that keeps one bad column from failing the whole query knew only the open table, so it read the other table's name and columns as unknown ones
- Saving a schema rewrote its file with a single definition, deleting every other table declared there — silently, since the tables stayed in the database with nothing naming them
- Opening a database could open a different one: the loader returned the head of the schema list, which meant "most recently added" only while schemata were pushed rather than appended
- Overwriting a database only asked; the file stayed with every table it held, so the import appended to rows that were already there
- A database label was lost on restart, so a multi-table database went back to being called after whichever of its tables came first
- Two docstrings ended early on unescaped quotes, which stopped the test suite loading and broke every cross-table column

* 0.5.4 (2026-08-19)

** Added

- Column formulas: ~tabularium-compute~ writes a computed column as an ordinary Lisp form, compiling to SQL where it can and to the existing post-fetch path where it cannot
- The column wizard asks for a formula directly: answering =y= to "Computed?" prompts for it, checks it against the operator table, and writes the complete =:computed (tabularium-compute ...)= into the schema file.  It used to leave a commented stub to fill in by hand
- =org= joins TSV and CSV as an export format, written pre-aligned and with pipes escaped as =\vert{}=
- =e c= copies the current view to the clipboard rather than a file, in any of the three formats.  With rows marked it copies those; with a prefix argument, every visible row

** Changed

- Sorting by a column adds to the sort rather than replacing it; a column already in the sort has its direction flipped in place.  =s X= discards the sort
- New =| F= edits a computed column's formula, offering the current one for editing
- A truth-valued formula renders as =TRUE= / =FALSE= rather than SQLite's 1 and 0
- The registry shows =DB= (file present) and =S= (schemata defined) instead of a single =Schema?= column
- 42 formula operators covering arithmetic, comparison, logic, text, dates, times, datetimes, and table-wide aggregates.  Each has a matching ~tabularium-fn-*~ helper of the same name, so the lambda form can do whatever a formula can; only the punctuation operators need a different name (~+~ is ~tabularium-fn-add~)
- ~datetime-diff~, ~datetime-add~, and ~datetime-subtract~ work across date, time, and datetime columns in any combination.  Durations are written =2Y 3M 3d 14h 35m=; a difference with no unit is a compound string in the same notation, so it can be fed straight back
- Counting offers computed columns
- The colon-based wizard method is called "shorthand"

** Fixed

- A column the table did not have took the whole query down with =no such column=, and with it the database — which could then not be opened to remove the column that was breaking it.  Every column is now checked against the table before it is named: a missing one reads =<<ERROR>>=, and sorting or filtering by one drops the clause
- A schema file with an error in it reported the same "no schema found" message as a schema file that was absent, and offered to create a database.  The failure is now recorded and reported: the file is named, the error quoted, and opening it offered
- Registry rows with a long path and a =(missing)= tag ran past the frame
- Almost every computed column rendered as =<<ERROR>>=.  The guard that catches a formula naming a deleted column scanned *inside* string literals, so =bulk= in ~THEN 'bulk'~ read as an unknown column — and with it every formula producing text, every date function, and every aggregate.  It now reads only the parts outside string literals, and knows its own generated identifiers
- A compiled formula was parenthesized twice: =((qty * price)) AS total=
- A formula written in a schema file was never compiled.  `tabularium-define-schema' is a function, so its columns arrive quoted and the `tabularium-compute' macro inside them never runs — the literal form reached the query, which emitted =NULL= for the column.  Formulas are now compiled where they are read, so the quoted and expanded spellings behave alike
- A computed column added through the wizard also had a real column added to the table, and that column of nulls shadowed the formula
- Rewriting a schema after an edit printed each column on one line, so a formula added through the wizard came out unreadable.  Both writers now render columns the same way, with `:computed' last and on its own line
- Importing an org file with several tables took the first one in silence when reached through =i i=; both entry points now offer the choice, and both reach unnamed tables
- Importing a table into an existing database could query the previous schema's columns against the new table.  View buffers are keyed by schema name, so a reused buffer kept a stale buffer-local name that outranked the global one
- Org cells arrived carrying the buffer's text properties, so a heading's =%= was consumed when used as a format string and =% Change= rendered as =Change=
- Declining a registry confirmation cleared the marks anyway

* 0.5.3 (2026-08-09)

** Fixed

*** Data integrity

- A find-and-replace whose result was invalid for the target column wrote it anyway.  Replacing =2026= with =20XX= put =20XX-05-18= into date columns, which SQLite accepts because dates are stored as text — and every later read of the column then failed, so the damage outlived the session.  All five replace commands now validate the result before writing
- Date, time, and datetime validation checks the calendar as well as the format, so =2026-07-89= and =2025-02-29= are rejected
- Substring search treated =%= and =_= as SQL wildcards, so a search for =50%= matched everything beginning =50=
- Statistics ordered values as text, so =1922= sorted before =-700= — the minimum, maximum, and every percentile were silently wrong on any column SQLite treated as text
- An integer first column was adopted as the primary key on import merely for being integers.  A blank in it was filled in by SQLite, and appending a second file discarded that file's identifiers.  A column is now adopted only if every value is present and no two repeat

*** Import and export

- A file whose headers collide after sanitizing failed at =CREATE TABLE=, and the half-registered schema left behind broke every later database open.  Colliding names gain a numeric suffix, and a failed import now unregisters its schema and removes what it wrote
- Column names that SQL will not accept — beginning with a digit, or empty after sanitizing — are corrected rather than passed through
- A file whose first column is not an integer failed on every row with =datatype mismatch=: a synthesized =row_id= was being lined up against the row values, shifting every column by one
- The export format followed a customization rather than the filename, so a file named =.csv= could be written tab-separated — and reimporting it produced a single column named after every heading run together
- Exports carry the column label rather than the internal id, and the destination prompt offers a usable default
- A newline inside an imported cell split its row in the view

*** Elsewhere

- Opening a database from a buffer that still carried a different one connected to the wrong file
- A computed column whose expression names a deleted column no longer breaks the view; the cell shows =<<ERROR>>= and the delete command warns first
- Stacked highlight rules resolve by rule number at every intersection, so the most recently added rule wins
- Aborting a query-replace with =C-g= left the replacements already made unundoable
- Removing a database left it in the completion list until choosing it failed
- A column added with a =:default= now fills the rows already there

** Changed

- Counting and aggregating are separate families on separate prefixes: =#= counts how many rows answer a description, =%= summarizes the values in a column.  Count offers the same rule types as filtering and highlighting, each with a variant scoped to the current view
- Filter and highlight rules can be negated as the *first* rule, and numeric and datetime filters offer eight interval comparisons: =[RANGE]=, =(RANGE)=, =[RANGE)=, =(RANGE]= and their =NOT= forms
- The filter and highlight dispatchers ask rule type and operand first, then target and scope, matching the direct commands
- Frozen rows are isolated from the view's filter, sort, and row limit, and are listed in freeze order
- Column show/hide, column reordering, freezing, and appending a file are all undoable
- New commands: =v= toggles a column summary between the common values and the whole list; =| $= / =. $= rename a column and =| l= / =. l= relabel one; =v X= expunges a saved view; =!= relocates a moved database
- =$= renames and =l= relabels under either prefix; =a= opens the action menu in a view and =A= in the registry, where =x= now closes
- Docstrings name commands rather than keys, so the reference stays correct for readers who bind their own
- The Emacs spelling =regexp= replaces =regex= throughout, including the schema property =:regex= → =:regexp=
- The quick-spec abbreviation for a primary key is =pri= rather than =pk=

* 0.5.2 (2026-07-24)

** Added

- Filter, highlight, and sort become one "rules" system: a shared rule vocabulary — substring, exact, regexp, numeric, datetime, and unique/duplicate tests — under matching keys, each with its own rules-list buffer (=f l=, =h l=, =s l=) for marking, removing, reordering, and inserting rules
- Rules carry a scope — rows, whole columns, or individual values — adding column filters (=f |=) and row- and column-scoped highlights to the existing cell rules
- The =f a= and =h a= dispatchers prompt for a row restriction and, for column rules, a column restriction (=<<ALL>>=, =<<RANGE>>=, or the marked rows); the direct keys stay restriction-free for speed
- Filter and sort changes are undoable
- Columns are added, inserted, and edited through the schema wizard's full column-definition prompts, and can be pasted from the kill ring (=| V= / =| A=)

** Changed

- "Layers" is retired for "rules" throughout, and filter, sort, and highlight share one keybinding vocabulary
- Filters and sorts accept computed columns, whether defined in SQL or in Emacs Lisp (Emacs-side evaluation is bounded by =tabularium-post-fetch-row-cap=)
- Highlight faces each set a single attribute under one naming convention, so stacked rules compose instead of the newest overriding the rest
- A keybinding-consistency pass moves several commands: duplicate to =+=, schema-save to =.=, database registration to =R=, and the shared rule-type letters (=s=, =e=, =r=, =n=, =t=)
- Column and rule commands default to the item at point, and the =f a= / =h a= target prompt defaults to the common case — =row(s)= for a filter, =value(s)= for a highlight
- Saved views row and re-pin frozen rows

** Fixed

- Sorting by a computed column works for SQL expressions and is refused, rather than silently ignored, for Emacs Lisp ones
- A filter rule whose query fails rolls back instead of wedging the whole stack
- Moving a filter rule keeps its connective, and column moves carry point along with the column
- Relative last-used times use singular units for a count of one (=1 week ago=)

* 0.5.1 (2026-07-13)

** Added

- =f f= (~tabularium-view-filter-at-point~) adds an exact-match filter on the cell value at point; computed columns, having no stored value, are rejected
- A *Sort Rules List* buffer (=s l=, ~tabularium-view-sort-buffer~) parallels the Filter and Highlight rules-list buffers, with the same marking, removal, reorder, and direction-cycle keys
- The database registry flags the open database with a =+= in the mark column and re-renders on open so the just-opened entry sorts to the top under point
- All three rules-list buffers (sort, filter, highlight) gain =M-p= / =M-n= (and =M-<up>= / =M-<down>=) to move the rule at point
- =s `= (~tabularium-view-sort-index~) sorts by the primary-key column; =s s= (~tabularium-view-sort-reverse~) now sorts by the column at point, the keyboard equivalent of clicking a header
- "Remove all" commands for sort (=s X=) and filter (=f X=), plus =X= in their rules-list buffers
- =F x= (~tabularium-view-fill-clear-to-point~) clears the column up to but not including point; the inclusive clear moves to =F X=
- =F S= (~tabularium-view-fill-series-up~) and =F D= (~tabularium-view-fill-delete-up~) add upward counterparts to fill-series and delete-run
- =F r= / =F R= (~tabularium-view-fill-replace~ / ~tabularium-view-fill-replace-up~) set a same-value run to a prompted value, downward or upward
- =z X= unfreezes all frozen rows as an alias for =z U=; both unfreeze aliases now appear in the freeze menus
- =| s= (~tabularium-view-show-columns~) reveals hidden columns, the inverse of =| h=
- ~tabularium-close~ is bound to =c= in the main menu, the bare command map, and the registry
- =z x= is an extra unfreeze alias alongside =z u=

** Changed

- Sorting now follows the same rules paradigm as filtering and highlighting: =s s= reverses, =s a= adds a key, =s c= cycles a key's direction, =s x= removes one key or all, and =s l= opens the rules-list buffer.  Views remain the way to persist a sort
- "Layers" terminology is retired for "rules" throughout the filter code and UI: ~tabularium-view-filter~ becomes ~tabularium-view-filter-add~, the internal stack is ~tabularium--filter-rules~, and sort, filter, and highlight now share one vocabulary
- =f a= is the filter-type dispatcher (was =f f=); in the Filter Rules List buffer =c= cycles the logical connective (was =j=)
- In all three rules-list buffers the plain arrows stay within the list and the cursor starts on the first rule
- A view's sort, filters, and visible columns persist across a quit (=q=) and reopen while the database stays open; closing the database resets them
- Counting folds "count across" into ~tabularium-aggregate-count~ (=# c=), which counts a single column or several via a ~completing-read-multiple~ with an =<<ALL>>= sentinel
- "Freeze marked" and "unfreeze marked" merge into ~tabularium-view-freeze~ / ~tabularium-view-unfreeze~, which act on the marked rows or the row at point
- ~tabularium-view-column-add~ follows the creation wizard's order (label, then slug) and always appends; use ~tabularium-view-column-insert~ to choose a position.  ~tabularium-view-column-edit~ matches that order
- Pasting a column mirrors row paste: =V= inserts at point, =A= appends
- ~tabularium-view-move-column-left~ / ~-right~ now register undo/redo, affecting only the buffer's display order
- Keybinding-consistency pass with the hydra displays as the source of truth: replace =R s= / =R S= / =R r= / =R R=, mark =* s= / =* e=, filter exact =f e=, visible count =# C=, fill delete-run =F D=
- The column-summary buffer uses the standard 80-character box width and a flat-indent layout with aligned =Value= / =Count= / =%= columns
- =F F= is now a true backward fill, the mirror of =F f=, propagating the value at point into the blank run above; ~tabularium-view-fill~ is renamed ~tabularium-view-fill-backward~
- Delete-run moves to =F d=, freeing =F D= for the new upward variant; across the directional fill commands the lowercase key acts downward and the uppercase key upward

** Removed

- Column-header click-to-sort (=mouse-1= / =mouse-3=) and its helpers; =^= is no longer bound
- The redundant column-specific paste commands =| V= / =| A=; standard =V= / =A= now handle columns
- ~tabularium-customize~ from the bare command map (still available via =M-x=)

** Fixed

- Hiding a column that a computed column depends on no longer blanks the computed column
- Removing a column in a table with computed columns no longer errors; this also fixes undoing a created column and cutting a column in such tables
- =<backtab>= no longer jumps multiple cells in tables with computed columns or near highlighted cells, and the spurious "Push this button" message is gone — faced cells are now propertized strings rather than buttons
- A stale ~tabularium-schema-show~ reference in the transient menus is corrected to ~tabularium-schema-view~
- The redo message now names the action being redone rather than its inverse

* 0.5.0 (2026-05-18)

** Added

- Highlighting (conditional formatting): a schema-level ~:highlight~ property and an interactive =h=-prefix command set that color rows and cells in view mode.  Rules are plists (~:scope~ ~row~/~cell~, a ~:face~, and a ~:test~ lambda, ~:value~ literal, or pure-data ~:builtin~ keyword); the three built-in cell types — ~compare~, ~duplicates~, ~regexp~ — round-trip through the schema file.  =h h= quick-highlights the marked rows, =h n= numeric/comparison, =h d= duplicates, =h r= regexp, =h a= the full new-rule dispatcher, =h l= an interactive Highlight Rules List buffer, =h x= remove, =h X= expunge, =h s= / =h S= save one/all.  Matching rules stack — background, foreground, and style faces compose — from the customizable ~tabularium-highlight-faces~ palette (ten WCAG-AAA hues × bg/fg, plus styles).  Add/remove is on the undo ring
- New ~time~ and ~datetime~ column types (=HH:MM[:SS]= and ISO 8601 timestamps), with ~:default now~ resolving per type via ~tabularium-time-format~ / ~tabularium-date-format~ / ~tabularium-datetime-format~
- Date/time arithmetic helpers for ~:computed~ lambdas, all nil-safe: ~tabularium-fn-time-now~, ~-datetime-now~, ~-time-add~, ~-time-diff~, ~-datetime-add~, ~-datetime-diff~, ~-datetime-date~, ~-datetime-time~, ~-datetime-combine~, ~-duration-format~
- Column-level validation properties: ~:pattern~ (case-sensitive regexp), ~:pattern-help~, and ~:validate~ (predicate).  Validation runs type → pattern → custom on every prompted edit; the first failure shows inline and re-prompts with the rejected value
- Three new database-creation paths alongside the wizard, under a =C= sub-menu and as ~tabularium-create-database-quick~ (one-line =id:type:flag= spec), ~-from-header~ (pasted header row), and ~-from-schema-file~ (a "Save As" mirroring an existing schema's columns, views, highlights, and backend)
- Registry-mode marking with marked-or-at-point operations: =m= / =u= / =U= / =t= mark, and =$= rename, =d= duplicate, =D= delete, =X= expunge, =e= export, =i= import act on the marked set or the database at point
- Field-type hints in entry prompts and (optionally, via ~tabularium-entry-show-type-hints~) in the form buffer
- Registry =/= opens the database's directory in Dired

** Changed

- Export is a four-way =e= prefix: =e e= ~tabularium-export~ (marked rows or whole table), =e a= ~-export-all~ (whole table), =e v= ~-export-visible~ (the on-screen view), =e r= ~-export-range~ (an explicit =3-7,12= ID spec and a column selection).  All four resolve computed columns and honor the TSV/CSV choice; =e e= now prompts for columns
- Import is split under an =i= prefix: ~tabularium-import~ (=i i=) always imports a file as a new, registered database; ~tabularium-import-append~ (=i a=) appends a file's rows to the open database, matching columns by column id then label and never writing the primary key
- Filter, highlight, and mark commands share one ~completing-read-multiple~ column selector (with a =<<ALL>>= sentinel); multi-column filtering is now built in, so ~tabularium-view-filter-across~ is removed.  =f f= is a type dispatcher (substring/exact/numeric); the substring command is ~tabularium-view-filter-substring~.  Filter layers carry ~:columns~ and an optional ~:op~ on one code path
- Logical-connective terminology replaces "join" throughout: ~tabularium-view-filter-cycle-connective~ (=f c=), the "Logical connective:" prompt, and the internal ~:connective~ key
- Clicking a column header sorts by it (=mouse-1= adds/flips an ascending/descending layer, =mouse-3= removes it), layering into ~tabularium--sort-columns~; sorted columns show a ~↑~ / ~↓~ indicator
- Saved views also capture the row restriction (~:rows~) alongside filters, columns, and sort; ~tabularium-view-show-range~ accepts the same =3-7,12= spec as ~-export-range~
- The auto-prepended primary-key column is renamed ~row_id~ (label ~ID~) from ~rn~; the docs call the concept the *row ID*.  Pre-release, so no compatibility alias
- ~tabularium-fn-now~ is renamed ~tabularium-fn-datetime-now~ and emits the space-separated form; pre-release breaking change with no alias
- The rules-list buffer commands are renamed for discoverability (~tabularium-highlight-*~ / ~tabularium-filter-*~, modes ~tabularium-highlight-mode~ / ~tabularium-filter-mode~); a *Filter Rules List* buffer (=f l=) parallels the highlight one
- ~tabularium-describe-database~ is reachable via =?= consistently (=SPC= stays the view menu), profiles an unopened database from disk, and gains the box ornament
- New ~tabularium-faces~ group consolidating all faces, with six new ones (list header, frozen row, sort indicator, modeline filter)
- The main menu orders import before export; =<= / =>= are alternative prefixes for import / export
- British spellings are corrected to American English throughout, the project's standard
- Performance on large datasets: bulk operations that write many rows — find/replace, fill, reindex, row move/cut/delete/duplicate/paste, import, and bulk undo/redo — are wrapped in a single database transaction instead of committing once per row, and view highlighting resolves its active rule set once per refresh rather than once per cell.  An EIEIO-level transaction protocol (`tabularium-db-with-transaction`) backs this, defaulting to a no-op on backends without transaction support

** Fixed

- Computed fields are now safe across read, insert, update, and export: ~tabularium-entry-submit~ strips computed fields before writing, ~tabularium--build-select-with-computed~ emits ~NULL AS name~ placeholders for elisp-computed fields, ~tabularium-export-range~ computes over the full row before projecting to selected columns, and import skips computed fields when aligning columns
- Prompt-entry and quick-entry now validate input the same way the form does, so malformed ~date~ / ~time~ / ~datetime~ / ~integer~ / ~number~ values are re-prompted rather than written; ~tabularium-fn-date-diff~ and ~-datetime-diff~ return nil on unparseable input
- ~tabularium-rename-database~ is now transactional and updates the registry under the correct ~:name~ key (closing connection, renaming the database/schema/WAL sidecars, rewriting the embedded schema, and reopening if needed)
- Duplicating a database with a symbol- or list-valued schema property (e.g., ~:default-sort~) now quotes such values, producing a loadable copy that registers correctly
- ~tabularium-describe-database~ now reads ~:file~ and ~:backend~ from the schema plist correctly (previously dropped the first key, masking PostgreSQL backends)
- ~tabularium-rename--make-slug~ now strips all punctuation via =[^a-z0-9]+=
- Cell-jump navigation is consistent in all four directions: column boundaries account for ~tabulated-list-padding~ and derive from one helper, movement uses ~move-to-column~ (robust to trimmed short rows), and the spurious back-step in the backward/up variants is removed
- Moving a filter layer no longer emits connective-less SQL; the connective invariant is restored after a swap and defended in ~tabularium--build-filter-clause~
- ~tabularium-view-fill-clear~ includes row #1 when it is the far end of the range
- Deleting a row in view mode keeps point on the same visual row
- Invalid-type error messages for ~integer~/~number~ are shortened to just the rejected value

* 0.4.8 (2026-05-17)

** Added

- Interactive view-save: =v s= (or =M-x tabularium-view-save=) captures the current visible state (active filter, sort spec, visible columns when customized) as a saved-view preset in one of 9 slots.  Prompts for the slot and a display name, persists immediately to the schema file, and updates the modeline.  The Views sub-hydra has a new "Save current" entry; the transient menu gains =v s= under View
- =tabularium-view-show-all= (=v a=) now wipes all view constraints (filter, sort, hidden columns, saved-view label) in addition to removing the row limit and ID-range — useful when the goal is "show me everything in this table."  The previous behavior (expand row count while keeping the active view) is now =tabularium-view-show-all-in-view= (=v +=)
- Search/replace history: ~tabularium-search-history~, ~tabularium-replace-history~, and ~tabularium-regexp-history~ are now wired into the find/replace prompts (mark-containing/equal/regexp, replace value/exact/regexp/query, count-value, all visible-scope variants, and the dynamic =Replace 'X' with:= prompts).  Press \\[previous-history-element] in any of these prompts to recall a previous value
- ~:safe~ predicates on simple-typed defcustoms (~tabularium-case-sensitive~, ~tabularium-debug~, ~tabularium-auto-reindex~, ~tabularium-view-page-size~, ~tabularium-view-sort-ascending~) so they may be set in =.dir-locals.el= without prompting
- Database creation wizard is now more walkthrough-style: each prompt explains what it's asking for, column names default to =fieldN= and are sluggified automatically, prompts default to a Title Case version of the column name, and the =boolean= column type is offered alongside text/integer/number/date/choice
- Wizard prompts are now breadcrumb-prefixed so the user remains oriented inside nested sub-prompts.  Each prompt shows the path of already-known attributes followed by the currently-prompted attribute.  Schema attributes appear in CAPS with an optional bracketed hint (default value, =empty to finish=); yes/no questions appear in Title Case ending with =?= and rely on `y-or-n-p''s built-in =(y or n)= suffix.  Example sequence:
  - =FIELD #1 > LABEL [empty to finish]: Patient Name=
  - =FIELD #1 > "Patient Name" > ID [patient_name]:= (RET accepts the suggested slug)
  - =FIELD #1 > "Patient Name" > "patient_name" > TYPE: text=
  - =FIELD #1 > "..." > "..." > text > Required? (y or n)=
  - =FIELD #1 > "..." > "..." > date > Default to today? (y or n)=
- Wizard now offers ~:width~ (column width) and ~:long~ (long-edit buffer) per field, plus the ~recent~, ~vocabulary~ (with file picker), and ~related~ (with sibling-field picker) completion sources in addition to ~historical~.  Advanced sources (~filtered~, ~function~, ~union~) remain configurable by editing the schema file directly
- Wizard can optionally insert a commented-out ~:computed (lambda (row) ...)~ placeholder line beneath the field, for users who want to add a computed value later without re-running the wizard

** Changed

- *Breaking rename:* the field-plist keywords ~:name~ and ~:prompt~ have been renamed to ~:id~ and ~:label~ throughout.  Pre-release, so no aliases are provided.  Hand-written schema files must be updated.  The registry and view definitions continue to use ~:name~ for non-field display names
- Undo records now use ~:row~ (and ~:row1~, ~:row2~) for the affected row primary-key value, and ~:column~ for the affected column name, distinct from field plists' ~:id~ and the registry's ~:name~.  Each plist sector now has unique keyword names so that an accidental rename or refactor cannot silently cross sectors

** Fixed

- Removed a trailing period from the user-error in ~tabularium-insert-entry~ to match Emacs convention
- ~tabularium-import--org-list-tables~ would hang in an infinite loop when called on multi-table org files; the helper invoked ~org-table-end~ but discarded its return value, leaving point inside the table.  The picker-style ~tabularium-import-org-select-table~ would have been affected on any file with at least one table
- Choice fields and fixed-completion text fields are now restricted to their declared candidate list when edited in entry mode (previously free text was accepted)
- The registry buffer now positions the cursor at the first database entry on open
- Boolean fields are now locked to a single canonical pair (Yes/No, True/False, 1/0, etc.) per column, optionally declared via a new ~:boolean-pair~ field property and otherwise inferred from existing column data.  The wizard prompts for the pair upfront when a boolean field is created.  Entry-mode restricts completion to the chosen pair (require-match) so the column cannot accumulate mixed conventions
- Entry-mode now validates field input at edit time using a single per-type validator: integer fields reject decimals, number fields reject non-numeric strings, and date fields reject anything other than =YYYY-MM-DD=.  Empty input is always accepted (for clearing a column).  The wizard's default-value prompts use the same validator, so an integer column's default cannot be a decimal and a date default cannot be an arbitrary string.  Error messages follow a uniform format: =Invalid X: 'value'.  Please enter Y=

** Changed

- Wizard prompts for an invalid field-name input (e.g., with spaces or punctuation) now explicitly offer the sluggified form rather than silently accepting it; entering an all-punctuation name re-prompts
- ~tabularium-create-database~ signals an error if the generated schema file fails to load, rather than continuing on to a downstream "No schema found" message

Both previously emitted a restricted-list field, but `:type choice' additionally produces a SQL CHECK constraint so the database itself enforces the restriction.
