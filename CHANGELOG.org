All notable changes to ~tabularium~ are documented in this file.

* 0.4.6 (2026-04-30)

** Added

- ~tabularium-customize~ — open the Customize buffer for the package
- ~tabularium-describe-database~ — display a summary of the open database (backend, file path, size, modification time, schema fields with type and constraints, total row count); shown in a dedicated =*Tabularium Database*= buffer.  Bound to =?= in ~tabularium-command-map~
- ~tabularium-schema-rename-field~ — focused single-property variant of ~tabularium-view-column-edit~ for renaming a field; updates both the database column and the schema file.  Bound to =. n= in ~tabularium-command-map~ and added to the schema sub-menus
- ~tabularium-entry-clear-and-edit~ bound to =X= in entry mode — clears the current field and immediately prompts for a new value, useful when overwriting an existing value with something unrelated

** Changed

- Customize hierarchy reorganized: defcustoms now grouped under themed subgroups (~tabularium-schema~, ~tabularium-database~, ~tabularium-display~, ~tabularium-entry~, ~tabularium-export~, ~tabularium-registry~, ~tabularium-menu~, ~tabularium-undo~) for easier navigation in the Customize browser
- ~tabularium--duplicate~ renamed to ~tabularium--duplicate-prompt~ and made truly private (no longer interactive); users invoke duplication through ~tabularium-view-duplicate~ or ~tabularium-entry-duplicate~

** Fixed

- Entry duplication via ~tabularium-view-duplicate~ and ~tabularium-entry-duplicate~ no longer leaves a blank form buffer.  The render call had been inadvertently dropped during a prior refactor when the new-entry hook was wired in

* 0.4.5 (2026-04-26)

** Added

- ~tabularium-view-column-paste-append~ bound to =| A=, mirroring row paste-append (=A=)
- Computed-field helpers for date arithmetic: ~tabularium-fn-today~, ~tabularium-fn-now~, ~tabularium-fn-date-add~, ~tabularium-fn-date-diff~, ~tabularium-fn-age~
- Computed-field helpers for cross-row lookup: ~tabularium-fn-lookup~, ~tabularium-fn-count-where~, ~tabularium-fn-sum-where~
- ~tabularium-db-build-equals-clause~ helper for safe SQL equality conditions
- ~tabularium-entry-edited-p~ — public predicate for plugins to detect unsaved form changes
- ~tabularium--field-accepts-value-p~ — singular schema validator used by fill and replace
- Plugin hooks for entry-mode lifecycle: ~tabularium-entry-pre-render-hook~ (set buffer-local variables before layout), ~tabularium-entry-new-hook~ (auto-populate fields on new entry creation), ~tabularium-entry-pre-submit-hook~ (mutate values just before save)
- ~tabularium-entry-required-field-functions~ — abnormal hook for declaring dynamic required fields (e.g. type-specific requirements); marked fields display `+' alongside the static `*' marker for `:required t'
- ~tabularium-entry-header-function~ — buffer-local function returning a header string inserted between the title bar and field list, for plugin-driven citations or summaries
- ~tabularium-command-map~ — prefix keymap exposing top-level commands without depending on ~hydra~ or ~transient~; users may bind it to any prefix key (see README "Bare Keymap" section).  Sub-prefixes ~.~ and ~#~ lead to ~tabularium-schema-command-map~ and ~tabularium-aggregate-command-map~
- Field highlighting in entry mode now follows point: clicking with the mouse or moving by ~goto-char~ updates the highlighted field, so =RET= always edits the field at the cursor
- Discard prompt now fires when an active form buffer is about to be overwritten by another entry, or killed via =C-x k= or window cleanup, protecting partially-filled forms
- Fill operations on `:choice` fields now offer the schema's choices as completion candidates and require a valid selection
- Replace and fill operations report the number of fields skipped due to schema constraints in their summary message (e.g. "Replaced 5 (2 protected)")

** Changed

- =:choices= field property renamed to =:choice= for consistency with the singular-keyword convention used throughout the schema vocabulary; existing schema files must be updated
- New namespaces:
  - ~tabularium-fn-*~ for computed-field helpers (~tabularium-fn-if~, ~-case~, ~-sum-fields~, ~-concat-fields~, ~-today~, ~-now~, ~-date-add~, ~-date-diff~, ~-age~, ~-lookup~, ~-count-where~, ~-sum-where~)
  - ~tabularium-aggregate-*~ for interactive math/statistics commands (~tabularium-aggregate-count~, ~-sum~, ~-min-max~, ~-mean-sd~, ~-median-iqr~, ~-column-summary~, plus ~-visible-*~ variants)
  - ~tabularium-sync-*~ for sync-related operations (~tabularium-sync-prepare~, ~-checkpoint~, ~-fix-paths~, ~-cleanup-wal-files~)
- ~tabularium-replace-*~ namespace consolidates visible-scoped variants (~tabularium-replace-visible-substring~, ~-visible-exact~, ~-visible-regexp~, ~-visible-query~) and renames ~tabularium-query-replace~ → ~tabularium-replace-query~
- ~tabularium-view-clear~ (was ~tabularium-clear-view~) and ~tabularium-completion-clear-cache~ (was ~tabularium-clear-vocabulary-cache~) regrouped into their respective subsystems
- ~tabularium--fields-accepting-value~ now returns =(ACCEPTED . REJECTED)= so callers can report protection counts in summary messages
- ~tabularium-db-build-like-clause~ takes an optional ~CASE-SENSITIVE~ argument; values are properly escaped and the operator (LIKE vs GLOB) reflects ~tabularium-case-sensitive~
- ~tabularium--paste-column-batch~ takes an optional ~POSITION~ argument; ='last skips the position prompt
- ~tabularium-fn-sum-fields~ coerces non-numeric and missing values to 0 instead of erroring; ~tabularium-fn-concat-fields~ skips empty and missing fields cleanly

** Fixed

- ~tabularium-entry-submit~ no longer triggers a spurious "unsaved changes" prompt: after a successful save, the buffer's original-values reference is updated so the kill-buffer hook recognizes the buffer as clean
- ~tabularium-entry-cancel~ no longer double-prompts: when the user has already confirmed "Discard changes?", the kill-buffer-query hook is bypassed for the actual quit
- SQL injection vectors in filter values closed: substring filters (~tabularium-find~, ~tabularium-view-count-across~, ~tabularium-last~), exact and numeric filter operators in ~tabularium--filter-layer-sql~, aggregate functions (~tabularium-aggregate-sum~, ~-min-max~, ~--get-numeric-values~), and the choice-field CHECK constraint at table creation all now route through ~tabularium-db-sql-quote~ or ~tabularium-db-build-like-clause~
- Substring filters honor ~tabularium-case-sensitive~ (previously always case-insensitive LIKE)

* 0.4.4 (2026-04-24)

** Added

- Fill-to-point commands =F ,= / =F .= (~tabularium-view-fill-up-to-point~ / ~-down-to-point~)
- Page navigation: =C-<down>= / =C-<up>= jump by ~tabularium-view-page-size~ rows
- Column scroll: =C-<right>= / =C-<left>= shift the viewport one column at a time
- ~tabularium-replace-visible-exact~ bound to =R E=
- ~tabularium-entry-current-field~ face (theme-aware light/dark variants)
- Plugin API expanded: ~tabularium-entry-editing-id~, ~tabularium-entry-schema-name~, ~tabularium-entry-render~ promoted to public
- README sections for the plugin API and computed-field helpers (~tabularium-fn-if~, ~tabularium-fn-case~, ~tabularium-fn-sum-fields~, ~tabularium-fn-concat-fields~)

** Changed

- Freeze keybindings restructured to a =z= prefix: =z z= / =z *= / =z u= / =z U= / =z x=; the prefix-arg toggle on ~tabularium-view-freeze~ replaced by separate ~-unfreeze~ and ~-unfreeze-marked~ commands; indicator changed from =❄= to =∙=
- =q= reserved for "quit" in all hydras: query-replace moved to =R /= / =R ?=, median[IQR] moved to =# i= / =# I=
- ~tabularium-replace-exact~ moved from =R == to =R e= for consistency with other replace commands
- Plugin API rename (single-dash public): ~tabularium-entry-all-nav-positions~, ~tabularium-entry-first-field-line~, ~tabularium-entry-footer-start~ (formerly ~tabularium-entry--*~)
- Internal API: ~tabularium-duplicate~ / ~tabularium-edit~ → ~tabularium--duplicate~ / ~tabularium--edit~; ~tabularium-db-checkpoint-all~ / ~tabularium-db-prepare-for-sync~ → ~tabularium-db--*~
- Schema-section keys in main transient use two-key sequences (=. .=, =. s=, =. r=, =. w=, =. +=) to match the keymap
- View transient filter-clear changed from =f c= to =f x= to match keymap and hydra
- View-mode buffer-local variables consolidated into Section 1.2 of ~tabularium.el~
- WAL/SHM cleanup moved to ~tabularium-db.el~ (~tabularium-db-cleanup-wal-files~) with thin wrapper in main file
- Modeline icon ~defface~ renamed to ~tabularium-modeline-icon-face~ (resolves collision with ~defcustom~ of same name)
- Modeline mouse-1 click now calls ~tabularium-menu~ (honors ~tabularium-menu-system~)
- ~tabularium-modeline-mode~ disable also tears down the awesome-tray module entry; segments self-deactivate via ~tabularium-modeline--active-p~, which now requires the mode to be enabled
- ~tabularium-view-show-more~ default increment is ~tabularium-view-page-size~ (was hard-coded 500)
- File headers reordered to FSF/GNU convention; ~Maintainer:~ and email added
- Hardcoded ~.schema.el~ replaced with ~tabularium-schema-file-suffix~ throughout
- Hardcoded ~#3a3a5a~ overlay color replaced with the new ~tabularium-entry-current-field~ face

** Fixed

- ~tabularium-schemas~ docstring covers all eight ~:complete~ types and the previously-undocumented field properties
- Fill commands report the actual count of cells changed (the ~filled~ / ~cleared~ counters were tracked but not reported)
- ~tabularium-sync-checkpoint~ now autoloaded; matching ~tabularium-sync-prepare~
- ~(require 'subr-x)~ added; forward declarations added for ~tabularium-transient~ and ~tabularium--kill-ring~
- PostgreSQL backend emits a one-time message when ~emacsql-pg~ is unavailable (was silent)
- README and KEYBINDINGS corrections: customization defaults, removed bindings that don't exist (=G=, =T=, =h=, =>=), added =* p= / =R E=, fixed column-clipboard key casing
- Six double-blank-line instances and trailing whitespace cleaned up; section numbering normalized in ~tabularium-menu.el~

* 0.4.3 (2026-04-06)

** Added

*** Plugin Interface for Entry Mode

- ~tabularium-entry-render-hook~ — hook run after form rendering with ~inhibit-read-only~ bound, allowing external packages to inject content (cross-table data, schema-specific hints, custom actions)
- ~tabularium-navigable~ text property — lines marked with this property participate in =TAB= / =S-TAB= navigation alongside schema fields, so plugin-injected content is keyboard-accessible
- ~tabularium-entry--all-nav-positions~ — unified navigator that merges field overlays and plugin-contributed navigable lines
- Hook fires after hint lines but before cursor positioning; plugins can read ~tabularium-entry--first-field-line~ and ~tabularium-entry--footer-start~ for layout context

** Fixed

*** Entry Buffer Rendering

- Symmetric 2-space left/right indent in the ornamental box display
- ~max-val-width~ set to 53 (80 − indent − label − separator − pad)
- Choices hint truncation rewritten: respects right padding, caps at 5 displayed choices with =…= overflow, and gracefully elides when the available column space is too narrow

* 0.4.0 (2026-03-15)

** Added

- Fill-at-point commands (=F F=, =F f=, =F d=, =F x=, =F p=) — zero-prompt fill operations that infer column and value from context
- Layered filter system (=f= prefix) with AND/OR/NOT logic, exact-match (=f ==), and numeric comparison (=f #=)
- View-scoped replace (=R R=, =R ==, =R X=, =R Q=) — find/replace restricted to visible rows
- Side-window entry display (~tabularium-entry-display~ = ~side~)
- Long-field editing (=:long t=) with dedicated buffer and ~tabularium-long-edit-mode~
- Sort layer management (=s s= / =s d= / =s x= / =^=)
- Entry mode position restoration on submit
- View-scoped math (=# M=, =# D=, =# Q=)

** Changed

- Keybinding overhaul: sort =s= prefix, fill =F= prefix, filter =f= with layer semantics, =0= resets across subsystems, uppercase = visible scope, =@= suffix = across columns
- Entry display default changed to ~side~
- Filter infrastructure rewritten from single SQL string to layered plist model (~tabularium--filter-layers~)
- Fill infrastructure unified under ~tabularium--fill-execute~
- RFC 4180-compliant CSV/TSV parser for multiline field import/export
- Scroll position preservation across refresh and entry submit

** Fixed

- Entry submit scroll position (cursor no longer lands at buffer end)
- Multiline field handling in import/export
- ~tabularium-prompt-entry~ nil display and missing view refresh

** Removed

- Old multi-step sort/filter with =<CLEAR>= / =<DONE>= sentinels
- Redundant fill wrappers and line-level CSV parsers
- ~tabularium-long-mode~ (replaced by ~tabularium-long-edit-mode~)
