#+TITLE: Default Keybindings
#+AUTHOR: Paul H. McClelland
#+OPTIONS: toc:nil num:nil

This file documents the default keybindings for ~tabularium~.  All bindings can be customized by modifying the relevant keymap (~tabularium-view-mode-map~, ~tabularium-entry-mode-map~, or ~tabularium-registry-mode-map~).

* View Mode (~tabularium-view-mode~)

** Navigation

| Key                  | Command                                       |
|----------------------+-----------------------------------------------|
| =n= / =p=                | Next / previous row                           |
| =TAB= / =S-TAB=          | Next / previous cell                          |
| ={= / =}=                | First / last row (same column)                |
| =[= / =]=                | Line beginning / end                          |
| =M-n= / =M-p=            | Jump to different value ↓ / ↑                 |
| =M-}= / =M-{=            | Jump to different value ↓ / ↑                 |
| =M-<down>= / =M-<up>=    | Jump to different value ↓ / ↑                 |
| =M-]= / =M-[=            | Jump to different value → / ←                 |
| =M-<right>= / =M-<left>= | Jump to different value → / ←                 |
| =C-<down>= / =C-<up>=    | Page down / up (by ~tabularium-view-page-size~) |
| =C-<right>= / =C-<left>= | Scroll viewport one column right / left       |
| =RET=                  | View entry details                            |
| =/=                    | Fuzzy find                                    |
| =g=                    | Refresh                                       |

Cell-jump navigation moves to the next cell with a different value, useful for grouped or sorted data: =M-]=/=M-[= step right/left, =M-}=/=M-{= step down/up, with =M-n=/=M-p= and the =M-<arrow>= variants kept as alternatives.  A prefix argument (e.g., =C-u 3 M-}=) jumps multiple value transitions.

Page navigation (=C-<down>= / =C-<up>=) jumps by the configured page size in either direction.  Column scroll (=C-<right>= / =C-<left>=) shifts the visible portion of the buffer one column at a time, useful when columns overflow the window.

** Sort (=s= prefix)

| Key | Command                            |
|-----+------------------------------------|
| =s s= | Sort by column at point (toggle, fallback index) |
| =s `= | Sort by index column (toggle)      |
| =s a= | Add sort rule (column + direction) |
| =s c= | Cycle a sort rule's direction      |
| =s x= | Remove sort rule(s) (=<<ALL>>= or one) |
| =s X= | Remove all sort rules              |
| =s l= | Open the Sort Rules List buffer    |

Sorting mirrors filtering and highlighting.  Sort keys are additive
rules: each =s a= adds another column (already-sorted columns are
excluded from the prompt), =s s= makes the column at point the sole
sort key (descending first, toggling on repeat — the keyboard
equivalent of a header click, falling back to the index column when
point is not on a sortable column), =s `= does the same for the index
(primary-key) column, =s c= flips a chosen key's direction, =s x=
removes one key or all of them (its prompt defaults to the =<<ALL>>=
sentinel), and =s X= removes every key at once.  A view is the way to
persist a sort, so there are no separate sort-save commands.  The
modeline shows the active keys joined with =∧=, each with a =↑= / =↓=
direction arrow (e.g. =author ↑ ∧ year ↓=).

=s l= opens the Sort Rules List buffer — an interactive list of every
sort key in priority order with its direction in a dedicated column.
From it, =m= / =u= / =U= mark and unmark keys, =t= toggles all marks,
=x= removes the marked keys (or the one at point), =X= removes every
key, =c= cycles the direction of the key at point, =RET= re-enters a
key, and =M-p= / =M-n= (or =M-<up>= / =M-<down>=) move a key up or down
to change its priority.  The buffer refreshes automatically as the sort
changes.

** Fill (=F= prefix)

| Key | Command                                |
|-----+----------------------------------------|
| =F F= | Fill gap ↑ (value from above to point) |
| =F f= | Fill forward ↓ (value from point down) |
| =F n= | Fill next ↓ (prompted)                 |
| =F p= | Fill prev ↑ (prompted)                 |
| =F s= | Fill series (number or date)           |
| =F .= | Fill ↓ to point (source above)          |
| =F ,= | Fill ↑ to point (source below)          |
| =F D= | Delete run (clear same-value cells)    |
| =F x= | Clear up to row (exclusive of point)   |
| =F X= | Clear through row (inclusive of point) |

=F F= and =F f= are zero-prompt: they infer the column and fill value from context.  =F n= and =F p= prompt for field and value.  =F .= and =F ,= are also zero-prompt and point-anchored: =F .= takes the nearest non-blank cell above and fills downward to point, while =F ,= takes the nearest non-blank cell below and fills upward to point.  =F D= clears the same-value run from point; =F x= clears the current column up to (but not including) a prompted row, and =F X= clears through it.

Without marks, fill operations auto-detect blank ranges from point.  With marks, they fill marked rows (prompting before overwriting non-blank cells).

** Highlight (=h= prefix)

| =h h= | Quick-highlight marked rows (or the row at point) |
| =h \= | Quick-highlight the column at point       |
| =h |= | Quick-highlight columns (=<<ALL>>= / comma-separated) |
| =h a= | New highlight rule (dispatches on rule type) |
| =h n= | Highlight by numeric/value/date comparison (> < >= <= = !=) |
| =h d= | Highlight duplicate values                |
| =h r= | Highlight cells matching a regexp         |
| =h l= | Open the Highlight Rules List buffer      |
| =h x= | Remove highlight rules (=<<ALL>>=, =<<UNSAVED>>=, or one rule) |
| =h X= | Expunge saved highlight rules from the schema |
| =h s= | Save one runtime highlight rule to the schema |
| =h S= | Save all current highlight rules to the schema |

=h h=, =h \=, and =h |= are quick highlights for fast on-the-fly work: =h h= prompts only for a face and tints the marked rows (or the row at point); =h \= tints the column under point; =h |= tints columns chosen from the selector.  All three add a real rule to the Highlight Rules List, so they can be removed, reordered, or saved like any other.  =h a= is the full dispatcher: it prompts for the rule type, then runs the matching command.  Each rule command prompts for the target columns with a comma-separated =completing-read-multiple= selector — the =<<ALL>>= sentinel (or an empty answer) targets every visible column, the same field-selection paradigm the filter and mark commands use; the chosen columns are echoed back in a =[...]= hint.  =h n= offers only columns where a comparison is meaningful — integer, number, date, time, and datetime — and because ISO date/time strings order chronologically as text, the same rule expresses "later/earlier than" for date columns.  Rules are additive and *stack*: when several rules match the same cell their faces compose, so one rule can add a background color, another a foreground color, a third bold.  Rules are numbered in evaluation order so the stacking hierarchy is visible.  =h x= removes rules — its prompt lists every rule, runtime and saved alike, and defaults to =<<ALL>>= (remove every rule); it also offers =<<UNSAVED>>= (remove only the session's unsaved rules) and each individual rule; removal never touches the schema file.  =h s= prompts for one runtime rule and persists just that rule; =h S= persists the whole view state; =h X= expunges the saved rules from the schema — these three are the only highlight commands that write the file.  =h l= opens the Highlight Rules List buffer, an interactive list where rules can be marked, removed, reordered, modified, added, and saved or expunged, all in one place.

** Filter (=f= prefix)

| Key | Command                         |
|-----+---------------------------------|
| =f a= | Add filter rule (dispatches on filter type) |
| =f f= | Filter on the cell at point (exact)         |
| =f s= | Substring filter                |
| =f e= | Exact match filter              |
| =f n= | Numeric comparison (> >= < <= = !=) |
| =f l= | Open the Filter Rules List buffer |
| =f c= | Cycle the logical connective (∧/∨/∧¬/∨¬) |
| =f x= | Remove filter rule(s) (=<<ALL>>= or one) |
| =f X= | Remove all filter rules         |

=f a= is a single entry point that prompts for the filter type — substring, exact, or numeric — then runs the matching command, parallel to the =h a= highlight dispatcher.  =f f= is a shortcut for the common case: it adds an exact-match filter on the value of the cell at point (reading the real stored value, so a truncated long field still matches in full; computed columns are rejected).  Every filter command prompts for its columns with the same =<<ALL>>= / comma-separated selector: pick one column, several, or all.  Filtering several columns ORs the test across them, so the old separate "filter across" command is no longer needed.  Filter rules are progressive and combined with logical connectives — the first sets the base; subsequent calls prompt for a connective (AND, OR, AND NOT, OR NOT).  =f x= removes one rule or all (its prompt defaults to the =<<ALL>>= sentinel); =f X= removes every rule at once.  The modeline shows the filter stack: =(genre = Fiction) ∧ (price > 20) ∧¬ (status ≈ inactive)=; when more than three rules are active the middle is elided to keep the modeline compact (=(genre = Fiction) … ∧ (year < 2000)=).

=f l= opens the Filter Rules List buffer — an interactive list of every filter rule, numbered in evaluation order with its logical connective in a dedicated column.  From it, =m=/=u=/=U= mark and unmark rules, =t= toggles all marks, =x= removes the marked rules (or the one at point), =X= removes every rule, =c= cycles the connective of the rule at point, =RET= modifies a rule, and =M-p=/=M-n= (or =M-<up>=/=M-<down>=) move a rule up or down the stack.  The plain =<up>=/=<down>= arrows stay within the list like =n=/=p=, and the cursor starts on the first rule.  The buffer refreshes automatically as the filter stack changes.

** Views (=v= prefix)

| Key     | Command                              |
|---------+--------------------------------------|
| =v v=   | Select saved view                    |
| =v s=   | Save current visible state           |
| =v 0=   | Clear all (filter/sort/cols)         |
| =v 1=–=v 9= | Apply schema view by number      |
| =v x=   | Clear all (filter/sort/cols)         |
| =v >=   | Show more rows                       |
| =v a=   | Show all rows (no constraints)       |
| =v +=   | Show all rows in current view        |
| =v r=   | Show ID range                        |
| =v ==   | Reset row limit to default page size |

=v 0= and =v x= both clear the active filter, column visibility, and sort back to defaults; =v 1= through =v 9= apply the corresponding numbered view from the schema.  The row-expansion keys control how many rows are shown: =v >= reveals the next page, =v a= drops every constraint, =v += lifts only the page-size limit and ID range while keeping the active filter, =v r= restricts to an explicit ID range, and =v == restores the default page size.

** Freeze rows (=z= prefix)

| Key | Command                                  |
|-----+------------------------------------------|
| =z z= | Freeze marked rows (or the row at point)   |
| =z u= | Unfreeze marked rows (or the row at point) |
| =z x= | Unfreeze (alias for =z u=)                  |
| =z U= | Unfreeze all frozen rows                   |

=z z= and =z u= act on the marked rows when any are marked, and on the
row at point otherwise (the same marked-or-at-point behaviour used
elsewhere); =z x= is a convenience alias for =z u=, and =z U= clears
every frozen row at once.  Frozen rows always render at the top of the
view, marked with a =∙= indicator.

Pasting a column uses the same keys as rows: =V= inserts the column at

the buffer's display and can be undone.

* Registry Mode (~tabularium-registry-mode~)

Action keys (=$=, =d=, =D=, =X=, =e=) act on the marked databases when any are
marked, otherwise on the database at point.  =i= imports a file as a new
database (it does not depend on the database at point).

The first column is a mark indicator: =*= marks a marked database and
=+= marks the database that is currently open (if a row is both, =*=
takes precedence).  Opening a database leaves the listing re-sorted
with that database at the top and under point.

| Key         | Command                                  |
|-------------+------------------------------------------|
| =RET= / =O= / =v= | Open and view database at point          |
| =o=           | Open database (no view)                  |
| =C=           | Create new database                      |
| =+=           | Register existing database               |
| =$=           | Rename (marked, or database at point)    |
| =d=           | Duplicate (marked, or database at point) |
| =D=           | Forget — keep files (marked, or at point) |
| =X=           | Expunge — delete files (marked, or at point) |
| =i= / =<=       | Import a file as a new database          |
| =e= / =>=       | Export (marked, or database at point)    |
| =.=           | Edit schema file at point                |
| =/=           | Visit database directory in Dired (other window) |
| =?=           | Describe database at point               |
| =m=           | Mark database at point                   |
| =u=           | Unmark database at point                 |
| =U=           | Unmark all                               |
| =t=           | Toggle all marks                         |
| =c=           | Close the open database                  |
| =x=           | Action menu (rename/duplicate/delete/expunge) |
| =g= / ===       | Refresh listing                          |
| =n= / =TAB=     | Next entry                               |
| =p= / =S-TAB=   | Previous entry                           |
| =q=           | Quit                                     |
