#+TITLE: Default Keybindings
#+AUTHOR: Paul H. McClelland
#+OPTIONS: toc:nil num:nil

This file documents the default keybindings for ~tabularium~.  All bindings can be customized by modifying the relevant keymap (~tabularium-view-mode-map~, ~tabularium-entry-mode-map~, or ~tabularium-registry-mode-map~).

* View Mode (~tabularium-view-mode~)

** Navigation

| Key                  | Command                                       |
|----------------------+-----------------------------------------------|
| =n= / =p=                | Next / previous row                           |
| =TAB= / =S-TAB=          | Next / previous cell                          |
| ={= / =}=                | First / last row (same column)                |
| =[= / =]=                | Line beginning / end                          |
| =M-n= / =M-p=            | Jump to different value ↓ / ↑                 |
| =M-}= / =M-{=            | Jump to different value ↓ / ↑                 |
| =M-<down>= / =M-<up>=    | Jump to different value ↓ / ↑                 |
| =M-]= / =M-[=            | Jump to different value → / ←                 |
| =M-<right>= / =M-<left>= | Jump to different value → / ←                 |
| =C-<down>= / =C-<up>=    | Scroll viewport down / up one row              |
| =C-S-<down>= / =C-S-<up>= | Scroll down / up a screenful                   |
| =C-S-<right>= / =C-S-<left>= | Scroll right / left a screenful             |
| =C-<right>= / =C-<left>= | Scroll viewport one column right / left       |
| =RET=                  | View entry details                            |
| =/=                    | Fuzzy find                                    |
| =g=                    | Refresh                                       |

Cell-jump navigation moves to the next cell with a different value, useful for grouped or sorted data: =M-]=/=M-[= step right/left, =M-}=/=M-{= step down/up, with =M-n=/=M-p= and the =M-<arrow>= variants kept as alternatives.  A prefix argument (e.g., =C-u 3 M-}=) jumps multiple value transitions.

The =C-= arrows scroll the viewport by one step on either axis: =C-<down>= / =C-<up>= by a row, =C-<right>= / =C-<left>= by a column, the latter useful when columns overflow the window.  Adding shift makes the same key move a screenful instead, so =C-S-<down>= / =C-S-<up>= page vertically and =C-S-<right>= / =C-S-<left>= page horizontally.  A screenful is the window's own size and is unrelated to ~tabularium-view-page-size~, which governs how many rows are fetched from the database.

** Fill (=F= prefix)

| Key | Command                                |
|-----+----------------------------------------|
| =F f= | Fill ↓ (context)                       |
| =F F= | Fill ↑ (context)                       |
| =F n= | Fill ↓ (prompted)                      |
| =F p= | Fill ↑ (prompted)                      |
| =F .= | Fill ↓ to point (source above)         |
| =F ,= | Fill ↑ to point (source below)         |
| =F s= | Series ↓ (number or date)              |
| =F S= | Series ↑ (number or date)              |
| =F d= | Delete run ↓ (same-value cells)        |
| =F D= | Delete run ↑ (same-value cells)        |
| =F r= | Replace run ↓ (same-value cells)       |
| =F R= | Replace run ↑ (same-value cells)       |
| =F x= | Clear down through a row (inclusive)  |
| =F X= | Clear up through a row (inclusive)    |

Lowercase fill keys act downward from point and uppercase keys upward.  =F f= / =F F= are zero-prompt: they infer the column and fill value from context, propagating the value at point into the adjacent blank run.  =F n= / =F p= prompt for column and value.  =F .= / =F ,= are point-anchored: =F .= takes the nearest non-blank cell above and fills down to point, =F ,= takes the nearest non-blank cell below and fills up to point.  =F s= / =F S= fill a number or date series.  =F d= / =F D= clear the same-value run from point; =F r= / =F R= replace that run with a prompted value.  =F x= clears the current column downward from point through a prompted row, and =F X= clears upward; both include the row at point, so they differ in direction only, like the rest of the fill keys.

Without marks, fill operations auto-detect blank ranges from point.  With marks, they fill marked rows (prompting before overwriting non-blank cells).

** Highlight (=h= prefix)

| Key | Command                                                     |
|-----+-------------------------------------------------------------+
| =h h= | Quick-highlight marked rows (or the row at point)           |
| =h \= | Quick-highlight the column at point                         |
| =h |= | Quick-highlight columns (=<<ALL>>= / comma-separated)        |
| =h a= | New highlight rule (dispatches on rule type)                |
| =h n= | Highlight by numeric/value/date comparison (> < >= <= = !=) |
| =h d= | Highlight duplicate values                                  |
| =h r= | Highlight cells matching a regexp                           |
| =h l= | Open the Highlight Rules List buffer                        |
| =h x= | Remove highlight rules (=<<ALL>>=, =<<UNSAVED>>=, or one rule)  |
| =h X= | Expunge saved highlight rules from the schema               |
| =h .= | Save one runtime highlight rule to the schema               |
| =h >= | Save all current highlight rules to the schema              |

=h h=, =h \=, and =h |= are quick highlights for fast on-the-fly work: =h h= prompts only for a face and tints the marked rows (or the row at point); =h \= tints the column under point; =h |= tints columns chosen from the selector.  All three add a real rule to the Highlight Rules List, so they can be removed, reordered, or saved like any other.  =h a= is the full dispatcher: it prompts for the rule type — substring (=h s=), exact (=h e=), regexp (=h r=), numeric (=h n=), datetime (=h t=), unique (=h u=), or duplicates (=h d=).  =h a= asks first what to highlight — =row(s)=, =column(s)=, or =value(s)= — and the same rule type then tints the whole row when its column matches, the whole column when any of its cells match, or just the matching cells.  Like the filter dispatcher, it can restrict a rule's reach: the column(s) branch to particular columns — tinting only those and leaving the rest — and the row(s) and value(s) branches to particular rows.  The row(s) and column(s) branches also offer a direct option that tints what is already chosen without a test — then runs the matching command.  The first five mirror the filter rule types, so the same vocabulary describes both; regexp and duplicates stay highlight-only, having no SQL equivalent in the built-in SQLite backend.  Each rule command prompts for the target columns with a comma-separated =completing-read-multiple= selector — the =<<ALL>>= sentinel (or an empty answer) targets every visible column, the same column-selection paradigm the filter and mark commands use; the chosen columns are echoed back in a =[...]= hint.  =h n= offers only columns where a comparison is meaningful — integer, number, date, time, and datetime — and because ISO date/time strings order chronologically as text, the same rule expresses "later/earlier than" for date columns.  Rules are additive and *stack*: when several rules match the same cell their faces compose, so one rule can add a background color, another a foreground color, a third bold.  Rules are numbered in evaluation order so the stacking hierarchy is visible.  =h x= removes rules — its prompt lists every rule, runtime and saved alike, and defaults to =<<ALL>>= (remove every rule); it also offers =<<UNSAVED>>= (remove only the session's unsaved rules) and each individual rule; removal never touches the schema file.  =h .= prompts for one runtime rule and persists just that rule; =h >= persists all current highlight rules; =h X= expunges the saved rules from the schema — these three are the only highlight commands that write the file.  =h l= opens the Highlight Rules List buffer, an interactive list where rules can be marked, removed, reordered, modified, inserted at point (=I=) or added at the end (=A=), and saved or expunged, all in one place.

** Filter (=f= prefix)

| Key | Command                                     |
|-----+---------------------------------------------|
| =f a= | Add filter rule (dispatches on filter type) |
| =f f= | Filter on the cell at point (exact)         |
| =f s= | Substring filter                            |
| =f e= | Exact match filter                          |
| =f n= | Numeric comparison (> >= < <= = !=)         |
| =f l= | Open the Filter Rules List buffer           |
| =f c= | Cycle the logical connective (∧/∨/∧¬/∨¬)    |
| =f x= | Remove filter rule(s) (=<<ALL>>= or one)      |
| =f X= | Remove all filter rules                     |

=f a= is a single entry point that prompts for the filter type — substring, exact, numeric, or datetime — then runs the matching command, parallel to the =h a= highlight dispatcher.  =f t= is the datetime filter: one command covers date, time, and datetime columns (ISO strings order chronologically as text), offering =before=, =after=, =exact=, and =range=.  =f u= and =f d= keep rows whose value in the chosen columns is unique or duplicated — the fastest way to find repeated rows.  =f |= adds a *column* rule: it keeps columns in which some cell satisfies the test (=any value= hides columns that are empty in the current view), joining the same stack as the row rules.  As a speed key it acts over every row and every column; the =f a= dispatcher is where a column rule can instead be judged over a subset of rows (a single index or a range such as =5-9=) or scoped to particular columns — hiding only those and leaving the rest.  A column rule marks both axes: =[…]= the rows it is judged over (shown only for a subset) and ={…}= the columns it acts on (={*}= every column), so a scoped rule reads =[5-9]{notes,tags}=.  To pick columns by what they are *called* rather than what they hold, use =| /=, which keeps the columns whose name or label matches and hides the rest (a prefix argument inverts it).  =f f= is a shortcut for the common case: it adds an exact-match filter on the value of the cell at point (reading the real stored value, so a truncated long column still matches in full; computed columns are rejected).  Every filter command prompts for its columns with the same =<<ALL>>= / comma-separated selector: pick one column, several, or all.  Computed columns are offered too.  One defined by a SQL expression is filtered and sorted by that expression; one computed in Emacs Lisp is filtered and sorted in Emacs after the rows are fetched, which means the page limit applies afterwards and the intermediate fetch is bounded by =tabularium-post-fetch-row-cap= (exceeding it reports an error rather than showing a truncated, wrong answer).  Such a column must be visible for this to work, since its value only exists on screen.  Filtering several columns ORs the test across them, so the old separate "filter across" command is no longer needed.  Filter rules are progressive and combined with logical connectives — the first sets the base; subsequent calls prompt for a connective (AND, OR, AND NOT, OR NOT).  =f x= removes one rule or all (its prompt defaults to the =<<ALL>>= sentinel); =f X= removes every rule at once.  The modeline shows the filter stack: =(genre = Fiction) ∧ (price > 20) ∧¬ (status ≈ inactive)=; when more than three rules are active the middle is elided to keep the modeline compact (=(genre = Fiction) … ∧ (year < 2000)=).

=f l= opens the Filter Rules List buffer — an interactive list of every filter rule, numbered in evaluation order with its logical connective in a dedicated =Op= column.  From it, =I= inserts a new rule at point and =A= adds one at the end; =m=/=u=/=U= mark and unmark rules, =t= toggles all marks, =x= removes the marked rules (or the one at point), =X= removes every rule, =c= cycles the connective of the rule at point, =RET= modifies a rule, and =M-p=/=M-n= (or =M-<up>=/=M-<down>=) move a rule up or down the stack, keeping each line's connective.  The plain =<up>=/=<down>= arrows (and =TAB=/=S-TAB=) stay within the list like =n=/=p=, and the cursor starts on the first rule.  The buffer refreshes automatically as the filter stack changes.

** View (=v= prefix)

| Key       | Command                              |
|-----------+--------------------------------------|
| =v v=       | Select saved view                    |
| =v .=       | Save current visible state           |
| =v 0=       | Clear all (filter/sort/cols)         |
| =v 1-9=     | Apply schema view by number          |
| =v x=       | Clear all (filter/sort/cols)         |
| =v X=       | Expunge saved view(s) from schema    |
| =v >=       | Show more rows                       |
| =v a=       | Show all rows (no constraints)       |
| =v +=       | Show all rows in current view        |
| =v r=       | Show ID range                        |
| =v ==       | Reset row limit to default page size |

=v 0= and =v x= both clear the active filter, column visibility, and sort back to defaults, leaving saved views alone; =v X= deletes saved view definitions from the schema file, the counterpart of =v .=; =v 1= through =v 9= apply the corresponding numbered view from the schema.  The row-expansion keys control how many rows are shown: =v >= reveals the next page, =v a= drops every constraint, =v += lifts only the page-size limit and ID range while keeping the active filter, =v r= restricts to an explicit ID range, and =v == restores the default page size.

** Freeze (=z= prefix)

| Key | Command                                    |
|-----+--------------------------------------------|
| =z z= | Freeze marked rows (or the row at point)   |
| =z u= | Unfreeze marked rows (or the row at point) |
| =z x= | Unfreeze (alias for =z u=)                   |
| =z U= | Unfreeze all frozen rows                   |
| =z X= | Unfreeze all (alias for =z U=)               |

=z z= and =z u= act on the marked rows when any are marked, and on the row at point otherwise (the same marked-or-at-point behavior used elsewhere); =z x= is a convenience alias for =z u=, and =z U= (or =z X=) clears every frozen row at once.  Frozen rows always render at the top of the view, marked with a =∙= indicator.

** Marks (=*= prefix)

| Key   | Command                              |
|-------+--------------------------------------|
| =m=     | Mark row at point (or active region) |
| =u=     | Unmark row at point (or region)      |
| =U=     | Unmark all                           |
| =t=     | Toggle all marks                     |
| =a=     | Action menu on marked rows           |
| =* s= | Mark by substring                    |
| =* e= | Mark by exact value                  |
| =* r= | Mark by regexp                       |
| =* p= | Mark by SQL pattern                  |
| =* n= | Mark by row range                    |
| =* #= | Count marked rows                    |

=m= and =u= act on the row at point, or on every row in the region when one is active; after marking at point the cursor moves down a row so runs can be marked in sequence.  =a= opens an action menu over the marked rows, falling back to the row at point when nothing is marked — the same marked-or-at-point behavior the fill, freeze, and export commands use.  The =*= commands select by value rather than by position, and add to any marks already set, so several passes can be combined.

Row-paste keys also handle columns: =V= inserts the copied column(s) at point and =A= appends them.  The =|= variants add a target prompt: =| V= inserts before a chosen column (defaulting to the one at point) and =| A= appends, both erroring unless the most recent kill-ring batch is a column.  =| s= re-shows columns hidden with =| h=, =| a= shows everything, and =| o= shows only a chosen set. Note that bare =+= duplicates the *row* at point (see Other, below); the column-add aliases are =| N= and =. +=.

** Count (=#= prefix)

| Key   | Command                          |
|-------+----------------------------------|
| =# s= | Count rows containing a value    |
| =# e= | Count rows equal to a value      |
| =# r= | Count rows matching a regexp     |
| =# n= | Count by numeric comparison      |
| =# t= | Count by date/time comparison    |
| =# u= | Count rows with a unique value   |
| =# d= | Count rows with a repeated value |
| =# a= | Tally all rows and columns       |
| =# #= | Tally visible rows and columns   |
| =# *= | Count marked rows                |

Counting mirrors the filter and highlight rule types — the three families ask the same question of a table and differ only in what they do with the answer.  Each key has a capitalized variant that counts within the current view rather than the whole table (=# S=, =# E=, =# R=, =# N=, =# T=, =# U=, =# D=), the same lowercase/uppercase split the fill and export families use.  =v c= is an alias for =# #=, since a tally of what is on screen is usually wanted while thinking about the view.

** Aggregate (=%= prefix)

| Key   | Command                          |
|-------+----------------------------------|
| =% s= | Sum                              |
| =% S= | Sum (visible rows only)          |
| =% m= | Min / max                        |
| =% M= | Min / max (visible rows only)    |
| =% d= | Mean ± standard deviation        |
| =% D= | Mean ± SD (visible rows only)    |
| =% i= | Median [Q1–Q3] (IQR)             |
| =% I= | Median [IQR] (visible rows only) |
| =% %= | Column summary                    |

Counting and aggregating answer different questions — how many rows match a description, against what the values in a column come to — so they have separate prefixes rather than sharing one.  Within each, lowercase covers the whole table and uppercase the current view.  =% %= reports on a column as a whole: how many rows hold a value, how many distinct ones, the most frequent, and the numeric block when the column is numeric.

* Registry Mode (~tabularium-registry-mode~)

marked, otherwise on the database at point.  =i= imports a file as a new
database (it does not depend on the database at point).

The first column is a mark indicator: =*= marks a marked database and
=+= marks the database that is currently open (if a row is both, =*=
takes precedence).  Opening a database leaves the listing re-sorted
with that database at the top and under point.

* Kill Ring Mode (~tabularium-kill-ring-mode~)

Opened with =y= from view mode; lists the row/column batches available to paste.

| Key       | Command                  |
|-----------+--------------------------|
| =V=         | Paste the selected batch |
| =X=         | Clear the kill ring      |
| =g= / ===     | Refresh listing          |
| =n= / =TAB=   | Next batch               |
| =p= / =S-TAB= | Previous batch           |
| =q=         | Quit                     |
