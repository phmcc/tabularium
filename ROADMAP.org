** v0.6.1 — joins

- [ ] A join is declared as a *view-like schema*: several tables, the columns to take from each, and the links to join on.  Reusing the read-only machinery means sorting, filtering, highlighting, and aggregating work on it the day it exists
- [ ] Export a join to CSV/TSV/Org, which is the case a join is usually wanted for
- [ ] Inner and left joins; the rest can wait for a case that needs them

** v0.6.2 — completing the relational baseline

Ordered by what blocks the most.

- [ ] *Schema and data, offered together.*  =i .= should ask whether there are data files for the tables it just declared, and a data import should ask whether a schema exists for what it just read.  These are one feature seen from two ends, and the answer decides which of the five schema methods applies — worth designing as one prompt rather than bolting a question onto each end

- [ ] *Schema migration.* Adding a =:foreign-key= to an existing table does nothing: SQLite adds constraints only at =CREATE TABLE=.  Today the only cure is to delete the database and rebuild, which makes the whole link feature usable on new databases only.  ~tabularium--rebuild-table-dropping~ already does the copy-and-swap dance for column deletion; generalizing it to "rebuild this table from its current schema" closes the gap and makes every constraint below retroactive
- [ ] *=NOT NULL= and =UNIQUE= in the DDL.*  =:required= is checked at entry and =:unique= does not exist; neither reaches the database, so anything writing to the file another way can break what the schema promises
- [ ] *=:on-update=.*  The delete policies are there; changing a parent key silently orphans its children
- [ ] *Composite keys.*  =:primary t= marks one field, and =:foreign-key= names one column.  A key of (patient_id, visit_date) cannot be expressed, which rules out a large class of real data.  Touches the storage layer, so cheaper before modularization than after

** v0.6.3 — repair

- [ ] =t ?= reports orphans; nothing fixes them.  Reassign, null out, or delete, on the rows it found
- [ ] Rebuild a table from its schema (the migration command above, exposed)
